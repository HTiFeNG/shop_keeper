# 店铺管家（shop_keeper）

商品管理 × 营业额记录 合并 App —— 一站式守店工具（Android + Web PWA）。

**当前版本：4.2.3**（数据安全与一致性修复：备份恢复的静默清空路径、编辑页编号、导出「假成功」等；完整变更见下方「版本变更」）

## 功能概览

### 营业额（首页）
- 日期切换记账；**跨零点自动切到新的一天**（柜台手机整夜开着也不会把早上的账记进昨天）。
- 从商品库选品自动带价；**扫码直接记账**（仅 Android）。
- **零售 / 批发两种计价方式**：选品时可切到批发价，明细行上的价签按钮可随时在「零售价 ⇄ 批发价」间切换并重算金额；同商品不同计价方式**不会**被合并成一行。
- **每条明细都显示商品品牌** —— 同名商品（比如两种「矿泉水」）一眼分得开。品牌在成交时随行定格；4.0.0 之前记的老明细会按商品编号回查商品库补上，不用等新记录才生效。
- 数量步进、单价编辑；总价默认 = 单价 × 数量，手动改写即解绑（抹零/改价）。
- 「最近常卖」快捷条：按最近 30 天销量自动生成，点一下记一笔，**不依赖手工加星**；有星标商品时优先显示星标。
- 删除行 5 秒内可撤销。
- 日合计大字：当日营业额 + 种类数 + 件数，固定悬浮在明细上方。

### 查账（跨日期明细搜索）
- 首页搜索图标进入；一次搜**所有日期**的明细（商品名 / 拼音首字母 / 品牌 / 条码 / 金额）。
- 时间范围快捷筛：今天 / 本周 / 本月 / 近 30 天 / 自定义区间。
- 结果按日期分组、组内显示小计；点日期可直接跳回那天的记账页。

### 统计
- 三种口径切换：**按月 / 自定义区间 / 按年**。
- 月视图：月总营收 / 日均 / 最高日 / 总件数四宫格，柱状图点柱子跳到当天明细，环比，商品排行前 10。
- **自定义区间**：任选起止日期，环比基准是「上一个等长区间」，避免拿 3 天去比 30 天。
- **年度总览**：12 个月完整折线/柱状，最忙的月份、平均月营收（按有营收的月份平均，不被空月拉低）。
- **估算毛利**：按「零售价 − **售出时的参考进价快照**」计算，之后修改商品进价不会改写已过去月份的毛利；亏本销售如实显示为负数；未填进价的明细会单独提示条数。

### 欠账本（赊账台账）
- 「更多」菜单进入。登记 客户 / 金额 / 日期 / 备注，支持标记已结清与撤销。
- 三种视图：未结清 / 已结清 / **按人汇总**（谁欠得多一目了然）；顶部显示未收回总额与逾期（超 30 天）提示。
- ⚠️ 欠账**不计入营业额**，只是台账 —— 不然「卖出去了」和「钱到账了」会被算两遍。要算营业额请在记账页正常记一笔。

### 跨端同步（坚果云 WebDAV）
- **不需要自建服务器**：用你现有的坚果云账号做中转，手机 ↔ 电脑互传备份。
- 配置：坚果云 → 安全选项 → 添加应用密码，填账号 + 应用密码 + 远端路径。
- 动作：测试连接 / 上传到云端 / 从云端恢复。
- 安全设计：**只读比对，绝不静默覆盖**。启动时会检查云端备份是否更新，若更新则弹窗给你选「查看并恢复 / 忽略」；恢复前照例存一份本机快照，可撤销。
- ⚠️ Web 端因浏览器 CORS 限制不可用，同步只在 Android / 桌面端生效；Web 端仍可用手工导入导出的 JSON 备份。

### 数据安全
- 全量备份 / 恢复（JSON）：恢复前**预览内容**（商品数 / 天数 / 明细条数 / 欠账条数 / 导出时间），恢复时**自动存一份恢复前快照**，可一键「撤销上次恢复」。
- 备份提醒：超过 7 天没备份会在首页提示，一键备份。
- 启动容错：单条数据损坏只跳过那一条，不再整体清空；整段损坏会明确报错而不是显示「暂无商品」。
- 保存失败会显式提示（不再「界面说已保存、实际没写进去」）。

### 商品管理
- 商品模型：名称、类别、品牌、条码、批发价、参考进价、零售价、星标收藏（编号自动生成）。
- **实时搜索升级**：商品名（含**拼音全拼 / 首字母**）/ 品牌 / 条码，按相关度排序 —— 完全匹配 > 条码 > 前缀 > 包含 > 首字母 > 全拼 > 品牌。输入 `kl` 能找到「可乐」，`nfsq` 能找到「农夫山泉」。
- **改分类只要两下**：商品行上的分类标签本身就是按钮，点它 →（面板里）点目标分类，完事。旧路径要「进批量模式 → 勾选 → 点移动分类 → 选分类」四步。
- 分类整理想调顺序？分类栏右侧固定的「⚙ 管理」图标按钮打开面板，**按住手柄拖拽**一次到位（不再是一次挪一格的上移/下移），也能就地改名、删除。
- 列表内直接加 ★。
- 批量操作（多选后批量移动分类 / 删除）、扫码（仅 Android）。
- 条码重复会被拒绝（否则扫码永远只命中第一个商品）。
- 商品表单：价格格式校验、零售价为 0 二次确认、未保存返回时提醒。

### 导出
- Android：Excel 双 Sheet（当日明细 + 月度汇总）经系统分享；Web：CSV 浏览器下载。
- 商品 CSV 导入 / 导出（导入会校验「编号」表头，选错文件不再静默导入垃圾数据）。
- 导出/导入失败会给出人话提示并可重试。

### Web / PWA
- 可「添加到主屏幕」，独立窗口运行，带启动遮罩（首帧前不白屏）与安装提示条。
- manifest 补齐 `id` / `scope` / `lang` / `display_override` / `orientation: any` / `categories`，iOS 侧补齐 `apple-touch-icon` 与状态栏 meta。

## 版本变更

### 4.2.3
一次针对「数据安全 + 一致性」的修复，来自对 4.2.2 的全量评审。

**数据安全（都是「未设防的静默清空路径」）**
- **修掉 v3 备份缺 `credits` 时静默清空欠账**。4.2.1 堵的是 v2 老备份（没有该字段），
  而「version 是 3、字段却被裁掉 / 类型不对」的备份会**绕过确认**把现有欠账清空。
  现在只要备份里拿不到**可用的**欠账数组（新增 `BackupPayload.hasCredits`），一律先要用户确认。
- **补上营业额侧的对称护栏**。此前只护了「备份里没有商品」，备份里**没有任何营业额记录**
  而本机有时，会把历史营业额整体清空且无提示 —— 现在同样要求确认。
- **恢复中断自愈现在会真的落盘**。旧实现发现 `sk_restoring` 标记后，只把快照换回内存、
  随即清掉标记：磁盘上仍是「新商品 + 旧营业额」的撕裂状态，而标记已清，下次启动不会再
  回滚，用户重启后读到的就是坏数据。现在按 `importBackup` 的同款做法做**内存 + 磁盘
  一起回滚**，写盘成功才清标记。
- **CSV 导入不再清空商品的名称 / 分类 / 品牌**。价格早就有「0 则保留原值」的保护，
  文本字段却是无条件覆盖 —— 导入一份「条码对、名称列为空」的 CSV 会把老商品名清成空。
- **日期键严格校验**。`2026-02-31`、`2026-13-45` 此前能通过正则，再被 `DateTime`
  规范化成 3 月 3 日之类，那天的数据就悄悄「跑到」了别的日期上。现在回比规范化结果挡掉。
- **`load()` 对商品编号去重**（备份解码路径早有同样的保护），避免重复 id 让
  `findById` / `updateProduct` 只命中第一条、编辑到错误的商品。

**正确性 / 一致性**
- **新增商品页不再在 `build()` 里取编号**。旧实现每次重建（改类别、切星标、弹键盘）都会
  消耗并写盘一个编号，且界面显示的编号与保存时再取的那个**对不上**。改为 `peekNextId()` 只读预览。
- **从统计页点柱子跳日期后，日期不再被静默拉回今天**。此前漏了同步 `_followToday`，
  跳到历史日期后一旦回到前台就被 `_syncToday()` 改回今天。
- **批量模式下切换分类 / 搜索词会清空已勾选**。否则勾选集合里留着当前**看不见**的商品，
  点「批量删除」会把它们一并删掉 —— 而商品删除没有撤销（明细行删除才有）。
- **导出备份的「假成功」修掉**。用户在系统分享面板里取消时，界面照样提示「备份已导出」，
  「N 天没备份」的提醒随之消失，而用户手上其实没有文件（临时目录还会被系统清理）。
  现在区分「已交出 / 已取消」，取消时不记为已备份。
- **CSV 公式注入防护**。名称 / 分类 / 品牌以 `= + - @` 开头时（如 `=cmd|...`），导出后
  Excel / WPS 打开会被当公式执行。现在前置单引号让 Excel 按文本处理，重新导入时自动还原
  （条码那条路径不受影响，它本来就用 `="..."` 强制文本）。
- **排序补显式二级键**（商品排行、最近常卖、欠账的三种视图、按人汇总）。项目已知
  **Dart 的 `List.sort` 不保证稳定**，此前只修了搜索的两处，其余并列项顺序会随机漂移。
- **`renameCategory` 对不存在的分类返回 false**，不再抛 `RangeError`。
- **分类名对话框的 `TextEditingController` 会释放**（此前每次新建 / 改名分类都漏一个）。

**其他**
- 坚果云配置的注释与实现对齐：应用密码**就是**和其余配置一起存在 shared_preferences，
  并没有 Android Keystore 存储（此前注释描述了一个未实现的机制）。`allowBackup=false` +
  `data_extraction_rules.xml` 这层防护照旧有效，应用私有数据不会进系统云备份。
- 文件选择不再用 `.single`（多选 / 空选会抛异常并被 catch 成「文件读不出来」，把用户引向错误方向）。
- `credit_page` 在 `await showDatePicker` 之后补 `mounted` 守卫。
- 新增 **7 条回归用例**（v3 缺 credits、营业额护栏、中断自愈落盘、非法日期、CSV 空值保留、
  公式注入往返、renameCategory 防御），测试总数 151 → **158**。

### 4.2.2
- **修掉导出的商品 CSV 里「条码」变科学计数法的问题**。导出的 CSV 用 Excel / WPS 打开时，13 位条码会被当成数字显示成 `6.090103E+12`；更严重的是**以 0 开头的条码会直接丢掉前导 0**（`0690103000000` → `690103000000`），拿这个文件回去核对就再也对不上。
  现在纯数字条码按 Excel 的**强制文本**写法输出（`="6090103000000"`），打开后显示完整数字；重新导入 App 时会自动还原，导出 → 编辑 → 导入的往返不受影响。非纯数字条码和旧版本导出的文件照常兼容。

### 4.2.1
一次针对「数据安全 + 同步可靠性」的修复，全部来自对 4.2.0 的逐行评审。

**数据安全**
- **修掉一个会静默清空欠账的路径**：v2 老备份不含欠账（credits）字段，而恢复是整体替换的 —— 升到 4.x 后记了一个月赊账，再恢复升级前的备份「商品和营业额回来了、欠账全没了」。现在这种情况会**先拒绝并说明会清空多少笔**，用户确认后才继续。
- **`items` 里的单条坏数据不再让整份数据作废**：解析改成逐条容错（与商品/欠账一致）。此前一条坏行会让 `load()` 抛异常 → `ready` 永远为 false → **App 卡在闪屏页**，同时内存已被清空、下一次保存就把空数据写回磁盘。
- **`load()` 改为「先全部解析完再整体赋值」**，并加了顶层 try/catch：任何意外都只置 `loadError`，绝不留下「清空一半」的内存，也绝不卡死启动。
- **恢复备份中途被杀进程可自愈**：写盘前先落一份完整快照并置 `sk_restoring` 标记，成功后才清标记。若在中间被杀，下次启动发现标记仍在就用快照回滚 —— 磁盘上那份「新商品 + 旧营业额」的撕裂状态不会再留成死账。
- **导入校验补强**：重复商品编号、重复欠账单号、负价格/负数量/负金额、非法日期、悬空日期键都会被跳过并计入跳过条数（此前一律照单全收，负金额还能把当日营业额拉成负数）。

**查账**
- **支持按品牌与条码搜索**（此前只传了商品名，行上明明显示了品牌却搜不到），页内提示语同步更新。
- **金额改为精确匹配**：旧实现用 `fmtPrice(...).contains(q)`，输 `1` 会把 ¥1.50、¥21.00、¥1000 全算命中，命中的汇总金额随之失去意义。
- **修掉日头行的横向溢出**：金额稍大（¥1,002.00）或系统字号调大时，那行会溢出。

**坚果云同步**
- **上传前先做覆盖冲突确认**：云端那份若与本机上次看到的不是同一份（另一台设备写过），先弹窗说明「继续上传会覆盖云端那份」，不再无条件覆盖。
- **「谁更新」改用远端文件修改时间做版本令牌**：只拿同一个服务端给出的值跟自己比，因此**不受两台设备时钟偏差影响**。旧实现拿远端 `exportedAt`（对方时钟）比本机 `lastSyncAt`（本机时钟）：时钟一偏就会误报「云端有更新」而覆盖掉本机新数据，或永远不提示。
- **「忽略」会被记住**：此前忽略只清内存，下次启动又问一遍（横幅上还没有忽略按钮），等于把用户训练成无脑点过。
- **不再每次启动都全量下载备份**：先用 PROPFIND 看文件时间做廉价判断，只有确实变过才下载。
- **同步配置类失败会显示出来**（密码错/路径错），不再静默；纯网络抖动仍静默。
- 修掉 `http.Client` 未关闭、上传时把目录错误误报成「远端文件不存在」、错误文案直接贴 HTTP 响应体等问题。

**凭据与隐私**
- **显式声明 `INTERNET` 权限**。此前它是由 mobile_scanner → ML Kit 传递依赖带进来的，哪天换掉扫码插件同步就会莫名全挂。
- **关闭 Android 自动备份**（`allowBackup=false` + 备份规则）：应用私有数据里有坚果云账号与应用密码，默认的自动备份会把它复制进 Google Drive，等于把整个网盘的读写权限带出设备。
- **Web 端不再提供同步凭据填写入口**：浏览器会拦截跨域 WebDAV，同步在 Web 上本来就用不了，原先却仍让用户输入账号密码并明文写进 localStorage。

**其他**
- 商品搜索：查询串去空格、索引侧也去空格（此前「500ml」搜不到「可乐 500 ml」）；拼音缓存淘汰改为**部分淘汰**，不再一超上限就整体清空重算。
- 搜索排序补上显式二级键（原下标）—— Dart 的 `List.sort` 不保证稳定，同分商品顺序此前可能每次都不一样。

### 4.2.0
这一版全部来自实际用了几天之后提的体验问题，没有新功能，只有「用起来顺不顺」。

- **改分类从 4 步降到 2 步**。商品行上的分类标签本身变成按钮：点它 →（面板里）点目标分类，完事。旧路径是「进批量模式 → 勾选商品 → 点底部"移动分类" → 弹窗里选分类」，而九成情况下店主只想给**一个**商品挪个位置。
  - 新增分类选择面板（当前分类打勾、面板内可直接新建分类并**建完即选中**）。
  - 批量移动分类复用同一块面板，不再单独维护一套弹窗。
- **分类排序改成拖拽**。「管理」面板里按住右侧手柄拖到目标位置松手即可，一次跨越任意距离；原来的上移/下移一次只能挪一格，挪 4 格要点 4 次还得每次重开菜单。
  - 手柄是**显式**的（关闭了默认的「长按整行拖动」）：长按没有视觉提示、还会和列表滚动打架，对中老年用户等于没这个功能。
  - 顺带把「＋分类」「管理」两个入口**固定在分类栏右侧**，不再随分类列表滚动 —— 原先它们排在滚动区末尾，分类一多就被推出屏幕（实测分类 2 个时「管理」的中心点已经落到 x=375.9，而屏幕只有 360 宽）。
- **营业额明细显示商品品牌**。同名商品一眼分得开。品牌在成交时随行定格；**4.0.0 之前记下的老明细**会按商品编号回查商品库当前品牌补上，升级后立刻可见，不用等新记录。手机卡片、宽屏表格、查账页三处统一。
- **修掉商品页标题被挤断**。原来是自绘的一行 `Row`，标题包在 `Flexible + 省略号` 里，右侧动作一多就被压成「商品…」。改成标准 `AppBar` 后由框架优先保住标题。
- **顶栏与分类栏的动作统一成纯图标按钮**。「新增 / 批量」和分类栏的「＋分类 / 管理」原先都带文字，四个彩色块挤在一起又宽又抢眼；现在和「备份」「查账」是同一套规格的标准图标按钮 —— 主操作「新增」用橙色点出、其余跟随默认色，每个都带 tooltip 说明用途。顺带把更多横向空间还给了标题（顶栏动作区 208 → 152dp），分类列表的可见宽度也多了 36dp。

## 开发说明

- 视觉规范统一在 `lib/theme/app_theme.dart`，页面不要散落硬编码颜色/字号。
- App **只提供浅色主题**并锁定 `ThemeMode.light`：全部页面颜色都取自浅色常量，跟随系统切深色会出现「页面浅、组件深」的错乱配色。
- 金额一律走 `lib/utils/format.dart`；日期一律走 `lib/utils/date_utils.dart`。
- 搜索一律走 `lib/utils/search.dart` 的 `SearchIndex`，不要在页面里手写 `contains`。
- 新增/修改存储相关的逻辑，请同步补 `test/services/` 下的用例；`test/helpers/store_test_env.dart` 提供 `resetStore` / `resetStoreWith` / `useSmallPhone` / `pumpApp`。
- **布局类测试一律用 `useSmallPhone`（360×640）**。`testWidgets` 的默认视口是 800×600，比真机宽得多，会**掩盖**「空间不足导致的溢出」——这个坑真的漏过一次（商品行里两个标签并排溢出 24px，单元测试全绿，直到 360 视口才暴露）。
- 商品行的可用宽度很紧张：360dp 屏上左侧只剩约 100dp（右侧三个 48dp 图标按钮吃掉 144dp）。往那一列加东西之前先算宽度。
- 数据默认只存在本机；开启坚果云同步后云端会有一份 JSON 备份。**Web 端没有同步能力**，改动存储字段时注意 `backup_codec.dart` 的版本号（`kBackupVersion`）与向后兼容。
- **应急工具**：本机偶发「Dart 无法创建子进程」故障（`flutter analyze` / `dart analyze` / `flutter test` 全部崩溃，报 `ProcessException: 所有的管道范例都在使用中 (CreateFile failed 231)`，`ProcessStartMode.detached` 反而正常）。此时用

  ```bash
  python tool/analyze_via_lsp.py
  ```

  做静态分析（等价 `flutter analyze`：由 Python 当 LSP 客户端驱动 Dart 语言服务器，绕开 Dart 的 fork）。它**只能**做静态检查 —— 跑测试和构建仍需在普通终端里进行。
